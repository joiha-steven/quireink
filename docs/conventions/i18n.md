# Localization — `locales/` (repository root)

- `types.ts` = shapes (`Dict` public, `AdminStrings` admin). Add a key → every locale file
  must define it (`satisfies` → build error otherwise = the no-missing-keys guarantee).
- `langs.ts` = `SITE_LANGS` + `isSiteLang`. Public `locales/<code>.ts`, admin
  `locales/admin/<code>.ts` — at the REPOSITORY ROOT since 2026-08-28, so a translator
  finds them without learning the tree (the import specifier stays `@/locales/*`; the
  root tsconfig maps it). Supported: **en (default), vi, de, ja, zh, ko, fr, es, pt
  (Brazilian), it, ru**. Register: de admin speaks Sie while de reader-facing strings
  (newsletter mails) speak du, both deliberate; zh speaks 你; ru speaks вы. No bundled
  face carries a CJK glyph, so CJK falls to a system face — a NAMED one, not the browser's
  last resort: `cjkLangCss` in `src/content/fonts.ts` emits a tail per language on
  `:lang(zh|ja|ko)`, because 直 is one codepoint drawn three ways and a font-family list
  never consults the language of the text.
- **Add a language:** extend `SiteLang`, add a `SITE_LANGS` row + a `DATE_LOCALE` entry in
  `i18n.ts` + both locale files. A Cyrillic/CJK language also decides its font story:
  `fontPreloadHrefs` skips preloads for ja/zh/ko/ru (no such glyphs in the preset
  subsets), and the OG card carries an Inter cyrillic subset so Russian titles render
  on share images (CJK titles still fall to tofu there — a CJK face is megabytes).
- **Add/rename a string:** add to `types.ts`, then fill ALL locale files. Build fails until
  complete. **Keep every locale in sync on any UI string change.**
